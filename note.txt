Here is why your database ended up in this state: The current schema running on Supabase was almost certainly auto-generated by your backend ORM (Hibernate/Spring Data JPA) using a setting like spring.jpa.hibernate.ddl-auto=update.

When Hibernate auto-generates a database schema from Java classes, it only does the bare minimum to make the code run. It creates tables and foreign keys, but it completely misses advanced database features, which is exactly what your teammate noticed:

1. No Default Values: Hibernate doesn't set DEFAULT now() or DEFAULT gen_random_uuid() at the database level.
2. Missing Constraints: Unless you specifically write complex @Check or @Table(uniqueConstraints=...) annotations in Java, Hibernate will not create CHECK constraints (for role validation) or compound UNIQUE constraints (to prevent duplicate memberships).
3. Missing Audit Timestamps: Hibernate handles @CreationTimestamp in Java memory, but it doesn't push the DEFAULT now() constraint down to the actual PostgreSQL table.
